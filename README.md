## Project Description
This project is a simple Student Management Application
created using HTML, CSS, JavaScript, Node.js, and Express.js.
The application was developed and executed using
GitHub Codespaces.

- Add students
- Edit students
- Delete students
## Technologies Used
- HTML
- CSS
- JavaScript
- Node.js
- Express.js
- GitHub
- GitHub Codespaces
## Cloud Networking
The application runs inside GitHub Codespaces.
The Node.js server listens on port 3000.
GitHub Codespaces forwards the application port so
that the web application can be accessed through
a browser.
## Cloud Security
Basic cloud security practices used in this activity include:
- No real student information was used.
- No passwords were stored in the source code.
- No API keys or credentials were committed.
- Port visibility was reviewed before sharing the application.
## Shared Responsibility Model
GitHub manages the underlying cloud infrastructure
used by GitHub Codespaces.
As the application developer, I am responsible for
the application code, repository access, credentials,
port configuration, and information stored or processed
by the application.

## Reflection Questions
### 1. What is the role of GitHub Codespaces in this activity?
GitHub Codespaces gives me a cloud workspace for coding. I can make changes, start my work, and run tests there. I do not need to set up all the tools on my own computer.
### 2. What is the purpose of port 3000?
To use the web app in a Codespace, you go through port 3000. Your browser uses that port to reach the app’s dev server and load what you need.
### 3. What may happen when the application port is made public?
Once the port becomes public, anyone might reach the app using the public link.
### 4. Which parts of the environment are handled by GitHub
or the cloud provider?
The GitHub platform and the cloud company run the servers for this setup. They also manage the cloud network, storage, and the Codespaces environment. You do not have to handle that side of things.
### 5. Which parts are your responsibility as the
application developer?
I write the application code and handle its day to day changes.  
I also set up the app settings and tune the configuration.  
After that, I test everything to make sure it works as expected.  
I take care of the dependencies too.  
I also guard sensitive data, like passwords and API keys.
### 6. Why should passwords, API keys, and other secrets
not be uploaded to a public GitHub repository?
They ought not to be uploaded since if the repository is public then anyone will be able to see and make use of them. This might result in unauthorized access to databases, accounts, or other services.
### 7. How does this activity demonstrate the
Shared Responsibility Model?
This activity demonstrates the Shared Responsibility Model because GitHub provides and manages the cloud development environment and infrastructure, while I am responsible for my project code, application configuration, and protecting my secrets
